# ADR-072: A stable `al-value` crate, and page state moves out of the value crate

- Status: Accepted (owner, 2026-11-10)
- Date: 2026-11-10
- Amends: ADR-008 (decision 4: the value model lives in `al-builtins`), ADR-010 (decision 1: `Value` is in `al_builtins::value`)
- Source: architecture review, section 1.2, 1.4 step A and "Do first" 4 (`~/.cache/al-runtime/fable-review/architecture.md`, local)

## Context

**Where we are.** `al-builtins` is the bottom crate. `al-ir`, `al-data` and `al-sema` depend on it, and so do `al-link`, `al-cache`, `al-deps`, `al-vm`, `al-testrun` and both command lines. Its `value.rs` (about 2,600 lines) holds `Value` and also the state structs of VM subsystems: `PageState` (about 615 lines, 230 public fields, 147 of them `bool`), `QueryState`, `FilterPageState`, `RecordState` and the HTTP states. It also holds the assumption registry (`assumptions.rs`, one file per entry in `assumptions/`, run by `build.rs`) and generated tables (`pinned_columns.rs`, `builtin_ids.rs`).

**The problem, in numbers** (14-day history, 1,576 source commits):
- 772 commits (49 %) touch `al-builtins` source.
- Each of them rebuilds about 340,000 lines (every crate above it).
- 406 of the 772 (53 %) touch only `assumptions*`, `value.rs`, `pinned_columns.rs`, `builtin_ids.rs` or `describe.rs` in that crate.
- 632 of the 772 (82 %) need neither `al-sema` nor `al-ir`, and still rebuild both.
- `value.rs` changed 99 times in 14 days, mostly together with `al-vm/src/pages/*` (24 times with `actions.rs`).
- `assumptions.rs` changed 202 times.

**Why `PageState` is there.** `Value::TestPage(Rc<RefCell<PageState>>)` must name the type. Nothing in `al-builtins` reads a page field. It only forwards through `Ctx::page` (`pagebuiltins.rs`, 123 lines). The type is used in six places only: `format.rs`, `ops.rs`, `describe.rs`, `value_codec.rs`, `native/values.rs` (builds `PageState::closed`), `native/ctx.rs`.

**The `Ctx` trait** (`al-builtins/src/native/ctx.rs`) has 76 methods. A new callback from a native into the session adds a method there and a body in `al-vm/src/ctx.rs`.

## Decision

1. **Add a crate `al-value`** at the bottom of the graph. It depends on `al-version` and external crates only. It holds what changes rarely and what upstream crates need:
   - `Value`, `RtType`, `Txt`, `ListVec`, `Instance`, `LibraryValue` and the core value types.
   - `RecordState` and its helper types (the store and natives both read them).
   - `ops` (compare), `filter` data, `value_codec`, `Describe`.
   - `BuiltinId` and `builtin_ids.rs`.
   - The catalog and signatures (`catalog.rs`, `signature.rs`, `catalog/*.txt`).
   - `Signal`.
   - The `Assumption` enum as ids only, with its compiler check (see 5).
   - What `al-sema` uses today from native modules (about 20 items: `native::lookup`, `platform::provider`, date-formula checks, conversion cells, `sysenum`, `dotnet_sigs`, `conv`). Each moves to `al-value` or becomes a generated table there. The migration plan decides item by item.
2. **`al-builtins` keeps the natives** and depends on `al-value`: format, evaluate, text, JSON, XML, HTTP, streams, dates, the registries, `Ctx`. Only `al-vm` and crates above it depend on it. `al-ir`, `al-data`, `al-sema`, `al-link`, `al-cache` and `al-deps` stop depending on it.
3. **Page and other client state moves to the crate that owns it.** `PageState` and its helper types (`WindowRow`, `Cursor`, `ReadBackwards`, `PageMode`, `ControlRef`, `ControlTarget` and the rest used only by pages) move to `al-vm` (`pages/`), the crate that reads and writes them today. `Value::TestPage` keeps a typed opaque handle: `PageHandle(Rc<RefCell<dyn Any>>)` in `al-value`, with a downcast helper in `al-vm`. A handle that does not hold a `PageState` is a bug and panics in tests. `QueryState`, `FilterPageState` and the page-only parts of the HTTP test states follow the same rule, in later steps, only if their fields are read by one crate. If the later page split of `al-vm` happens (a separate ADR, not decided here), the state moves again with the code and `al-value` does not change.
4. **Narrow `Ctx` by splitting it into traits by area** (`PageCtx`, `HttpCtx`, `RecordCtx`, `ClockCtx`, and so on), all still implemented by `Session` in `al-vm`. Natives take `&mut dyn Ctx` where `Ctx` is a supertrait combination, so call sites do not change. Page methods on `Ctx` take the opaque `PageHandle`, not `PageState`. The split is by method area and is mechanical. It does not change the seam: natives still call the session only through a trait object.
5. **Assumption registry and generated tables.**
   - The `Assumption` enum (ids) lives in `al-value`, so `al-ir` and `al-sema` can name it. It changes with each new assumption, so this is the one volatile item left there. To keep the rebuild small, the enum is generated by `build.rs` into its own small module, and everything else about an assumption (the `Info` text, `awaiting`, the run-time marking and report) lives in `al-builtins`. If measurement shows the enum still costs too much, the ids move to a leaf crate `al-assumptions` that `al-value` re-exports. That is an additive change and needs no new ADR.
   - `pinned_columns.rs` is used only by natives and the VM. It moves to `al-builtins`.
   - `builtin_ids.rs` is used by `al-ir` and `al-sema`. It stays in `al-value` and changes only when a builtin is added to the catalog.
6. **Public behavior does not change.** Every step is a move or a split. No `Value` variant changes meaning, no outcome changes, no baseline line changes.

## Migration

Every step is one behavior-preserving pull request. Every pull request carries the measurement below. Order matters: each step stands alone, so we can stop after any of them.

**Measurement for each pull request** (numbers go in the description):
- On a clean target dir, `cargo build --release --timings` once on `main` and once on the branch.
- Then the touched-crate rebuild: touch one file in the crate named in the step and run `cargo build --release --timings` again, before and after. Record wall time and the list of crates rebuilt.
- `cargo test -p al-test-cli --test fn_length_ratchet --test os_access_ratchet --test file_size_ratchet` and the corpus ratchet in PR CI stay green. No local full gate.

**Steps**
1. **Opaque page handle.** Add `PageHandle` to `al-builtins` (still one crate). `Value::TestPage` holds it. `PageState` stays where it is. Fixes the six `al-builtins` uses to go through the handle (accessors for what `format.rs`, `ops.rs`, `describe.rs`, `value_codec.rs` need: the object id, the open or closed flag). Measure: no change expected. This proves the seam.
2. **Move `PageState` and its helper types to `al-vm/src/pages/`.** Keep `PageState::closed` as a constructor the VM provides through `PageCtx`, so `native/values.rs` no longer builds one. Measure: touch `pages/actions.rs` and add a `PageState` field. Expect `al-builtins` and everything below the VM to stay built.
3. **Move `QueryState`, `FilterPageState` and page-only HTTP state** the same way, one pull request per type, only when the fields are read in one crate. Each type is checked first (grep for readers); a type read by natives stays.
4. **Split `Ctx` into area traits** inside `al-builtins`. No crate change. Measure: the build time of `al-builtins` and `al-vm`, which should be about equal.
5. **Create `al-value`.** Move the files listed in decision 1 with `git mv` so history follows. `al-builtins` re-exports `al_value::*` from `lib.rs` (and `pub use` for modules that moved), so `al_builtins::value::Value` keeps working while callers migrate. Measure: touch `assumptions` and `value.rs`, before and after.
6. **Repoint `al-ir`, `al-data`, `al-sema`, `al-link`, `al-cache`, `al-deps`** to `al-value` one crate per pull request, then delete the re-exports. Measure: touch a native file in `al-builtins`. `al-sema` must not rebuild. This is the step that shows the gain.
7. **Move the assumption `Info`, `awaiting` and report code** to `al-builtins`, and `pinned_columns.rs` with it. Keep the enum and its compiler-checked ids in `al-value`. The registry test (every id has one entry, ids checked by the compiler) moves to where the entries are, and still runs in `cargo test`.
8. **Update docs** (`docs/architecture.md`, `docs/codemap.md`) in the pull request of the step that moves the code, not later.

Expected effect from the review (an estimate, to be replaced by the measurements above): the 82 % of `al-builtins` commits that need neither `al-sema` nor `al-ir` rebuild about 265,000 lines instead of 340,000; a page fix stops touching the bottom crates and rebuilds about 200,000; median build time for those commits drops 20 to 35 %. If step 6 shows less than 15 %, we stop and report before step 7.

## What does not change

- ADR-008's catalog design: signatures generated from the docs, ids per overload, implementations registered by id, `AR1001` for a missing implementation. Only the crate that holds the catalog files changes.
- ADR-010's value rules: one `Value` enum, value types copy, reference types share, records are handles, UTF-16 text semantics, `Value::default_for`. Only the crate path changes (`al_value::Value`).
- The seam between natives and the session: `&mut dyn Ctx`, implemented by `Session` in `al-vm`. It is narrowed, not replaced.
- The `Store` trait (ADR-003, 004, 035), the IR (ADR-036), the engine and session split (ADR-001, 002), the compile cache format, the hard rules (no guessing, refusal over silent run, assumptions registered in code).
- `al-vm` is not split by this ADR. A page split of `al-vm` needs its own ADR after the owner decides it.
- All outcomes, error texts, baselines, metrics and corpus files.

## Risks

- **Large mechanical move.** About 100 files change imports. Mitigation: re-exports during the move, one crate repointed per pull request, the compiler finds every miss.
- **Merge conflicts with parallel agents.** `value.rs`, `pages/*` and `assumptions` are hot. Mitigation: do steps 1 and 2 first and quickly, announce the move in the agent brief, and merge `main` into open branches before each step lands. Agents keep adding assumption files meanwhile (they do not conflict).
- **Opaque handle costs a downcast per access.** One type check per page operation. Page operations are not the hot path (the review measured the interpreter, not the page client). If a profile shows otherwise, store the concrete type behind a generic parameter instead of `dyn Any`; that is local to `PageHandle`.
- **The `Assumption` enum stays volatile in `al-value`.** Mitigation in decision 5: separate generated module, leaf crate if needed.
- **A gain smaller than estimated.** The estimate is not measured. Every pull request measures, and step 6 has an explicit stop.
- **Ratchets.** Moving files can change `file-sizes.toml`, `fn-lengths.toml` and `os-access.toml` paths. Update the keys in the same pull request. Caps never go up.
- **Compile cache.** The cache key may include type paths of serialized values. Step 5 checks this and bumps the format number only if needed.

## Consequences

- `al-value` is a stable bottom crate. A native, a new assumption entry text or a page flag no longer rebuilds `al-sema`.
- `al-vm` owns the page client state it already owns in practice.
- `Ctx` is smaller per area and easier to read.
- One more crate in the graph, one more `Cargo.toml` and dependency line to keep.

## Conformance

- Each migration pull request carries its before and after timing.
- `cargo metadata` check in a test: `al-ir`, `al-data` and `al-sema` do not depend on `al-builtins` (added in step 6).
- `al-value` has no dependency on `al-builtins`, `al-vm` or any crate with OS access (ADR-006 ratchet).
- Existing tests, the corpus ratchet and `builtin_ids_current` stay green. The registry test (every assumption id has one entry) keeps running.
